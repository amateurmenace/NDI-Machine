## Architecture

Use C++20, MSVC, CMake, and the official NDI and Blackmagic Desktop Video SDKs for media processing. Use a separate C# WPF interface on a supported .NET LTS release. Use TypeScript and the current official Companion module template for the Companion integration.

Introduce these boundaries incrementally:

1. A supervisor/control host for configuration, command validation, health, and recovery.
2. Up to four independent channel workers, each owning its NDI reception, media conversion, audio mixing, and DeckLink output.
3. An external-audio capture host that opens each selected ASIO driver once and captures WASAPI endpoints. Split hosts by driver if testing requires isolation.
4. Separate GUI and Companion clients.

Closing the GUI or losing Companion must not stop healthy media outputs. Workers retain their last committed configuration during control connection loss.

Use bounded queues, explicit buffer ownership, RAII, preallocated media pools, and appropriate Windows multimedia scheduling. Keep logging, UI activity, network waits, expensive conversions, and unbounded allocation out of output/audio callbacks.

Distribute external audio through timestamped bounded buffers with independent readers. A slow reader must not block capture or another output.

Keep full-rate media out of REST/WebSocket messages and managed GUI code.

## Audio requirements

Each output needs these modes:

- Follow selected video’s NDI audio.
- Fixed audio source.
- Custom mix.

Support WASAPI recording endpoints. Optional playback-endpoint loopback must be explicitly enabled, with monitoring kept out of the capture loop.

Define one normalized internal floating-point audio convention. Convert NDI levels using the documented calibration before mixing with ASIO/WASAPI PCM. Provide SMPTE, EBU, unity, and custom input calibration separately from operator faders.

Initially embed a 48-kHz stereo mix on SDI channels 1–2. Keep the matrix extensible, but do not assume the ATEM can independently mix every channel DeckLink can transmit.

Clock-adapt each input against its destination output. NDI frame sync handles NDI inputs; external PCM requires a tested adaptive resampler/clock controller. Fixed nominal sample-rate conversion alone is insufficient.

At 30000/1001 fps, 48-kHz audio averages 1601.6 sample frames per video frame. Use continuous audio scheduling or an integer rational accumulator, never a constant rounded block count.

Preserve known NDI audio/video timing. Provide measured alignment for unrelated Dante/USB sources. Implement delay as bounded buffering; compensating for late audio may require delaying video.

On external-audio failure, remove only that contribution while video and other audio continue. Discard stale buffered samples after reconnect. Do not substitute Windows Default when a configured device disappears.
