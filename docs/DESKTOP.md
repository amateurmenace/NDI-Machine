# NDI Machine desktop

For the public portable EXE package, see [Windows download and startup instructions](https://github.com/amateurmenace/NDI-Machine/blob/main/docs/WINDOWS-DOWNLOAD.md). The public ZIP excludes private commissioning and does not replace an already-running installation.

Launch **NDI Machine.exe** from the complete package folder (currently `dist/NDI Machine-0.5.2` on the commissioned workstation). The GUI is a self-contained x64 WPF executable with .NET 8.0.32. Keep `engine`, `launcher`, `build/Release`, `config` and `notices` beside it. Installed NDI Runtime, Desktop Video and Microsoft VC++ x64 runtime are prerequisites; proprietary runtimes are not bundled.

On the commissioned workstation, the **NDI Machine** desktop shortcut opens this installed EXE with its package folder as the working directory. The copied A-drive EXE is recognized by executable hash and connects through the fixed installed launcher; it is not a replacement for the complete package.

The GUI connects to the local engine at port 9860. Closing it leaves media and control running. **Start control host** launches the packaged host when offline, with receivers idle. Saved settings never auto-start receivers. Opening the GUI itself never prepares outputs or switches the Videohub. **Production** is the default view for ordinary routing: choose each slot's source, audio and SDI connector in **Edit output**. Its health counters describe actual output operation independently of the emergency plan, and ordinary editing works without Companion. A read-only Companion poll supplies the live ATEM destination labels. **Failover** displays the emergency plan and Companion status. The view is remembered in private `config/local.desktop.json`; selecting either mode changes no media or routes. Already-running workers survive GUI/control restarts. The dashboard shows those actual workers and explicitly explains background receiving. Use Stop source or Engine controls to stop them; reopening a window is not a fresh media session. When no worker is running, the output and its source editor are empty until Apply or PRIME.

The optional lightweight launcher listens on localhost port 9861. Run `scripts/Register-Launcher.ps1` to start it and register it for the current user's Windows sign-in; `-NoStartup` starts it for this session only. On this commissioned workstation it is registered. It launches only this package's GUI/control host when Companion's **CLICK TO PRIME** is pressed. Companion then explicitly prepares the emergency preset, without changing Videohub routes or ATEM/Zoom audio. A separate press performs the toggle. No media or GUI is automatically started merely by the launcher signing in. To remove sign-in registration, remove the `NDI Machine Launcher` value from `HKCU:\Software\Microsoft\Windows\CurrentVersion\Run`.

## Output controls

Desktop 0.6.0 adds optional production routing through the existing **Companion module 0.6.0**. In **Edit output**, check **Also route Videohub to the ATEM when I apply**, select ATEM Input 1–8 and Apply. The checkbox starts unchecked. The operation prepares and confirms the selected physical output before routing its commissioned Videohub input to the selected ATEM destination (Videohub outputs 33–40). It unlinks a cloud replacement on that destination, without changing ATEM program, preview or mixer settings. Leaving the checkbox unchecked retains source-only editing.

For an already-running source, select the destination on its card and press **Route to ATEM**. **Return default** restores only that selected destination. **Return ALL to default** in the main sidebar shows the full saved map for confirmation, then restores all eight destinations. These return actions unlink cloud replacements and leave receivers running. Defaults come from the existing Companion production map, verified against current routes before this update; temporary production routing never changes those saved defaults. Offline or busy routing disables these controls while ordinary output editing remains available.

Source preparation failures do not route the Videohub. A selected connector must have a commissioned physical mapping, and an output feeding another unselected destination cannot be retuned through this combined action. Router locks, changed workers/settings and concurrent route changes are checked before TAKE. An uncertain write is reported without automatic replay or rollback.

The four cards are ordered and labeled **ATEM Input 1, 2, 3, 4** using the commissioned physical connector map. Each shows its NDI Machine slot and Videohub input underneath, plus the current live ATEM destination(s). The primary label is the commissioned destination; ordinary routing can send that connector elsewhere. If Companion is unavailable, live mapping is explicitly unavailable. Commands and previews remain tied to the physical slot.

**Edit output** opens the source, receiver, DeckLink and audio controls for that slot:

- Exact NDI source name and optional transport address (IP with optional port or the SDK's vendor HX address), populated from discovery.
- Highest or lowest receive bandwidth. Low bandwidth changes the actual SDI source quality; it is not required for GUI thumbnails.
- Fit/letterbox, fill/crop or stretch sizing. Output stays 1920x1080p30000/1001 UYVY for the commissioned ATEM. Other received sizes/rates are converted. Matching UYVY is copied exactly; other sizes use nearest-neighbour SDR scaling. The SDK deinterlaces and frame-synchronizes the input. HDR conversion is not implemented.
- Any enumerated compatible, free DeckLink connector by persistent identity. No profile changes, index-based assignments or stealing occupied outputs. The commissioned OBS Key/Fill card is reserved. Changing connectors interrupts only that output after preparation; incompatible or unavailable hardware is rejected.
- Audio from an explicit Windows capture endpoint, a Windows playback device's loopback mix, the selected NDI source, or silence. Windows device defaults are never changed. This is WASAPI shared mode, not ASIO or per-application process capture.
- Independent left/right channel selection, mute, gain from -60 to +12 dB and 0-500 ms additional audio delay. Stereo 48 kHz is embedded on SDI channels 1/2. This selects one stereo source per output, not a multi-source mixer.

Settings prepare before frame-boundary commit. Confirmation requires actual worker identity, displayed operation and revision; timeouts are never replayed automatically. Confirmed settings are saved, but only outputs explicitly started during the current engine session are eligible for recovery. An occupied or unknown ownership mutex prevents takeover. A changed connector or old-worker upgrade requires a short worker restart. Other outputs remain independent.

**Prepare backups**, visible in the Failover view, deliberately restores the commissioned sources/connectors and highest bandwidth: Dante USB I/O Module receive 1/2 at unity on the commissioned connector feeding **ATEM Input 1**. On this workstation that is **NDI Machine 2 / Videohub input 6**; the other three failover outputs are silent. The GUI derives this label from the plan. It does not change Videohub routes, Zoom or ATEM audio. The Companion failover button performs this restoration automatically when pressed over production assignments, waits for healthy emergency media, then takes Network. It may release/restart this application's own reassigned connectors, including cycles; it never steals unknown owners or the reserved OBS card. Hold three seconds and release to restore the saved production settings, crosspoints and ATEM/Zoom mix. This undo snapshot lasts only for the current Companion session. Opening the app, selecting a mode and background polling never invoke takeover.

**Stop source** releases that receiver and SDI output. **Engine controls** can stop all sources, stop the background engine, or restart it idle. These commands leave Videohub crosspoints unchanged. Use **Return default** or **Return ALL to default** to restore Videohub routing separately. Ordinary output editing works without Companion.

The [Companion quick router](PRODUCTION-ROUTER.md) offers source → Input 3/4 → TAKE on one screen, with More inputs for all eight.

## Discovery and monitoring

Sources are discovered automatically when the GUI connects and refreshed before an output editor opens. The picker shows every returned source, with editable name entry and its own **Refresh sources** button; refreshing preserves the pending selection. Discovery does not open video receivers. **Discovery / IPs** saves up to 32 external sender IPs and an optional group list, then refreshes discovery. Select the returned named source in an output editor. The IP must be reachable and the sender must expose an NDI source; this is not an RTSP/HTTP decoder. The editor also accepts a direct NDI transport address when known. Discovery can only list sources visible to the runtime's network/group configuration; it is not a guarantee of every sender across isolated networks.

GUI previews reuse the already decoded output through bounded local shared memory: 320x180 BGRA, at most 4 fps, no additional NDI connection or network subscription. The GUI can pause previews. A stale, failed or mismatched revision clears its preview. Previews are optional and never block SDI scheduling; they do not prove downstream signal.

Expand **Receiver statistics & audio meters** for input dimensions and advertised frame rate, measured arrival rate, receiver connection count, video/audio totals, receiver drops and queue depths, SDI late/dropped/fallback/repeat counters, stereo peak dBFS, clipped samples, configured gain/delay, audio buffer occupancy and clock correction. These are SDK/software observations, not network bitrate or end-to-end latency measurements. Codec and hardware-decode selection are managed by the NDI runtime; the standard SDK does not establish which codec/decoder is active.

Windows GPU counters observed VideoDecode activity for all four commissioned HX3 workers on this workstation. Video scheduling, conversion, previews and external-audio resampling use CPU work. External audio is adapted to the SDI consumption clock to control drift; this does not establish lip-sync. Measure picture/sound alignment at the ATEM and set audio delay accordingly. Physical listening, calibrated lip-sync and sustained soak tests remain unqualified.

**Diagnostics** saves local state, source/device identities and recent GUI activity. Review before sharing. The map in the sidebar is a commissioned plan; Companion provides live crosspoint verification. **Open Companion** opens the current emergency controls. The desktop does not duplicate that emergency sequence.

## Build

Run `scripts/Build-Desktop.ps1` after building native targets. `-NativeBuildDirectory build\preview\Release` selects an isolated native build; `-OutputDirectory 'dist\NDI Machine-staging'` builds separately from a running package. `-IncludeLocalConfiguration` creates a private workstation package; do not publish that directory or zip. The script runs control tests, publishes the GUI, host and launcher, and copies owned native executables plus open-source notices. All build/package products are ignored by Git.

See Microsoft's [single-file deployment documentation](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview), [NDI receiver documentation](https://docs.ndi.video/all/developing-with-ndi/sdk/ndi-recv), and [WASAPI loopback documentation](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording). GUI, control and media remain separate processes so a GUI closure cannot stop SDI.
